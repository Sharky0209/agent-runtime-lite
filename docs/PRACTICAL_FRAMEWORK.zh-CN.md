# Agent Runtime Lite：框架定位与可运行的业务场景

它是**单机任务执行与结果验收框架**：开发者提供普通命令和产物验收条件，ARL 负责持久化任务、启动子进程、记录尝试、管理依赖、判断什么结果可以放行。它不是大模型、Prompt 平台、分布式队列或自动化聊天续聊服务。

## 五层结构

| 层次 | 业务应用负责 | ARL 负责 |
| --- | --- | --- |
| 任务定义 | 命令、依赖、产物要求 | 稳定任务标识、工作流预检 |
| 执行 | Node.js/Python/其他 CLI 脚本 | 后台子进程、尝试记录、资源约束 |
| 验收 | 业务字段、文件或外部读回规则 | 本地文件检查、完成门禁、完成依据 |
| 恢复 | 判断重跑是否真的安全 | 持久状态、明确的恢复与人工复核 |
| 系统接入 | API 凭证、传输、真实收件方回读 | 外部操作登记和对账状态，不代替外部核验 |

已有的 `Runtime`、`previewFlow`、`runFlow` 和 `arl` CLI 就是公开入口。本次不额外造一套抽象框架或常驻服务。

## 实战：账单核对 → 独立验收 → 报告

从 GitHub **当前源码**克隆后，Node.js 20+ 下执行：

```sh
npm run demo:orders
# 给每批输入单独保留一个状态目录
node examples/order-audit/run.mjs ./my-audit-run
```

第一次运行时，如果 `./my-audit-run/invoices.jsonl` 不存在，会复制 4 条合成账单作为演示输入。替换成真实数据时，请**先创建目录和输入文件，再首次执行**。每行一个 JSON 对象，包含 `id`、整数分单位 `amountCents` 和 `status`（`paid` 或 `pending`），避免浮点货币误差，也不必引入 CSV 第三方解析器。

三个子进程依次执行：

1. `build`：检查字段、重复单号、金额，写 `audit.json`；运行时要求文件新鲜且 `status=ready`。
2. `verify`：**另一个进程重新读取原始账单**，比较全部统计值，写 `verification.json`；要求新鲜且 `status=verified`。
3. `render`：根据已核验的统计值输出 `summary.md`，脚本读取报告确认内容，再写 `rendered.json`；运行时核验本次的 `status=rendered` 回执。

样例结果：4 笔、已支付 3 笔、总额 **205.75**、实付 **160.25**。命令返回持久化的 `taskId`、各阶段状态及执行次数、报告路径。后续可以使用：

```sh
node bin/arl.mjs status --root ./my-audit-run --task TASK_ID
node bin/arl.mjs plan --root ./my-audit-run --task TASK_ID
```

同一个目录重复运行，会复用已经完成的任务，**不会重新执行三阶段**。新一批输入请新建状态目录；不要在已完成的目录里偷偷替换输入并期待自动重新计算，它不是文件监控器。

**异常路径也有测试：**重复账单号或非法金额会让构建失败，后续验收、报告不启动；中途篡改审计汇总后，独立验收拒绝通过。失败作业不会自动重试，先核实再决定是否重跑。

```sh
node --test test/order-audit.test.mjs
npm test
```

**必须区分的边界：**独立核账和 Markdown 读回由示例脚本实现；ARL 此处验的是三个 JSON 回执，不会自行解析 `summary.md` 或证明财务规则正确、远端业务已成功、文件一定由指定进程写入。当前源码另支持对非 JSON 文件直接按最小大小检查 `fileCheck.minBytes`。网络发送需要应用自己执行真实收件方回读，并通过操作登记、对账再确认。详见[接入指南](INTEGRATION.md)。

此案例属于**当前尚未发布的源码功能**，不在 `v0.2.0-beta.2` Release 安装包里。

## 其他落地用途

| 场景 | 任务编排 | 应当如何验收 |
| --- | --- | --- |
| AI 自动生成日报 | 抓取本地数据 → 生成日报 → 审核 | 文件字段检查，必要时人工审稿 |
| 本地构建/制品打包 | 构建 → ZIP/PDF → 后续交付 | 新鲜文件与大小检查，真正打开/安装再验 |
| 批次数据对账 | 录入 → 独立重算 → 输出汇总 | 对原始输入重新读取，校验统计字段 |
| 邮件/API 通知 | 准备 → 派发 → 对账 | 收件方真实回读，不以命令退出码代替送达 |

新接入项目可以从 `examples/order-audit/run.mjs` 复制工作流定义并替换实际命令，保持每批输入独立状态目录。无须把整个业务系统迁进 ARL。
